# S25 - Independent final reader, editor and journal-compliance audit

For an initially approved package or changed science, obtain the actual explicit S24 author
request/acceptance and verify its exact frozen upload version. Give exactly one independent
reviewer the actual files, current official instructions and neutral questions. It reads as
a new clinical reader, screens as an editor, and checks submission completeness/cross-file
consistency. All actionable findings in every section require a disposition, not only the
must-fix list. A truncated response or a typed PASS is not a complete independent report.
Include substantive Medical presentation observations about actual main/supplement prose,
table titles/cells/notes and figure labels/marks/legends. First read without backstage context,
then check the evidence. The report's actual Verdict must PASS, not just the workflow state.

Do not add a reporting form, registration or disclosure wording by default. Do not expose
patient/private data to external tools without authorization. No extra reader copies/ZIPs
unless explicitly requested. Missing evidence remains pending. Scientific facts take priority
over token/time savings; source-traceable NEW results are not automatically cosmetic edits.

A proven meaning-preserving presentation amendment reuses prior approval lineage after its
real scoped checks; no automatic S19 rewind, new full audit or repeated user confirmation.
A genuine scientific correction needs authorized owner repair and affected scientific review.
Final audit does not mean actual submission. AUTHOR_FINAL_COPY is an explicit handoff mode;
it cannot invent an independent verdict or waive objective scientific defects.

Use full details for report schemas, freeze verification, closure and author-final-copy path.

## Full procedure, read once when needed
`reference/stage_details/S25_submission_audit.md` (`tools/wf.py card S25_submission_audit --details`).
On first execution read the applicable detailed procedure; later local corrections reuse
already-read guidance and go directly to affected owner rules. After compaction use
`tools/wf.py handoff`, then retrieve only missing context. The actual gates remain unchanged.
`reference/structural-quality.md` v1.17 explains runtime fixes and preserved boundaries.

## Outputs
- `08_submission/independent_submission_audit.md`

If an independent agent is unavailable, perform a clearly labelled preliminary local check,
preserve the pending independent audit and report the exact blocker. Never claim independence
or final PASS for that fallback. Reuse an audit of unchanged upload bytes/context; repeat only
when the package/context changes or a material defect warrants it. Verify release hashes and
read-only attributes immediately before actual upload; preview working copies must not
replace the release.

## Close
Run `tools/wf.py check` (or the active scoped revision check). Fix actual failures before
`tools/wf.py advance --note "<actual completed work>"`. Stages are not turn boundaries.
Review stages still require the real author statement; generic continuation is not approval.
