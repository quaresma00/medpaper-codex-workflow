# MedPaper Codex Workflow

一套面向医学与临床研究的 Codex 工作流。它把“研究想法”推进为经过数据、文献、统计结果、图表、人工复核和期刊规则共同校验的投稿包，而不是只让 AI 一次性写出一篇看似完整的论文。

当前版本：`1.20.0`　｜　流程：25 个阶段　｜　运行环境：Windows + Codex

## 1.20 版：让科学判断跟随真实证据，避免无止境分析

这次从流程本身查出了三个上游问题：旧的发表判断可能被新结果继续沿用，分析停止条件过于绝对，以及真实但没有摘要的文献被一律排除。修正沿用现有阶段和文件，不增加默认报告或人工审批。

- **“可以写论文”必须针对当前研究。** 分析完成和发表可行性判断在作出时绑定方案、结果、代码及临床解释。随后科学输入改变，不能只重新冻结文件就沿用旧判断；执行器须重新评估发生变化的证据。无需重跑未变化的模型，也不因修改图注或内部笔记而重开分析。旧版冻结保持原有身份，不伪造历史判断。
- **分析以解决问题为终点。** 完成主要、次要结局和必要有效性检查后，追加模型要说明它可能改变哪个科学判断。取消“直到所有后续分析都不会改变结论”的无限任务，也不要求所有敏感性分析支持同一方向。阴性、矛盾及无法估计的结果按真实含义报告，不靠事后效能计算或挑选有利结果包装论文。
- **保留真实结果，隔离失效版本。** 不再要求删除“放弃的结果”。合法的阴性或矛盾结果保留；真正算错或被修正替代的任务生成版本可留在内部退役目录，注明原因和去向，并退出当前数值来源池。不能按显著性或方向决定保留哪些结果。
- **文献身份和可读内容分开验证。** 没有 PubMed 摘要不再自动排除原始方法论文；这类来源须取得身份核验、文件校验均通过的可读全文，才能正式引用。摘要仍保持为空，不能由 AI 补写。已有摘要也必须与真实来源一致，不能只核对标题、DOI 后就把改写内容当原文。检索次数不再是任务量配额，依据真实论证缺口补检索。

使用入口不变。科学判断和停止规则见[写作准备与增量工作](reference/efficient-quality.md)，文献操作见[文献库阶段](pipeline/stages/S13_reflib.md)。这些机制核对证据版本和来源，不能代替执行器对研究有效性与医学意义的实际判断。

## 1.19 版：医学读者能读懂，修改只处理真正受影响的内容

这次重点检查“规则写了，但实际执行仍可能漏掉或重复”的地方，不增加阶段、默认审阅代理或额外报告。

- **先讲研究，再讲实现。** 正文按研究问题、人群或样本、比较、结局和不确定性组织；表格标题、单元格和脚注一起读，图片里的标记、文字和图注一起读。读者不应打开代码或内部记录才能理解论文。真实统计方法、医学算法和探索性分析仍须说明，不能为了“去工程味”掩盖方法或夸大临床意义。
- **补充材料也要符合医学论文表达。** 最终检查纳入实际上传的补充 Word/PDF；能定位明显助手口吻、内部路径、工作流字段和草稿残留。参考文献标题不当成作者文风，不同表的脚注不再混在一起误报。同一句话不能复制到每个图表充当医学验收。
- **编辑与读者审阅明确检查医学性。** 新版投稿审阅和最终审计都要给出实际医学阅读观察，不能只写“格式通过”。科学有效性问题可以保留在其真实审阅章节，不必为了让工具接受而塞进“可读性”栏目；每条问题仍须处置。
- **审后修改先定位，再制作。** 一次理解整批意见，确定源文件、受影响产物、保持不动的材料和验收条件。含义不变的措辞或排版修改走局部修订，验证后沿用已批准版本的审批关系；真实科学错误只修对应分析及依赖，并完成必要的科学复核。删除了终审卡中无条件回跳、再次整轮审核的旧指令。
- **复用检查既省时也有依据。** 局部检查不再丢掉其他仍有效的凭据；关闭修改轮次时，对来源、规则、配置及依赖变化逐项判断。期刊副本、作者事实和说明性常量来源也参与身份核对，防止错误复用。实时、未知或失效的检查仍按要求执行，不延长有效期来换速度。

这不是“AI 文本检测器”：任何词表都不能保证医学理解。真实相近论文对标、执行器主动阅读、实际图表和页面检查、必要独立审阅仍共同承担质量控制。旧审阅记录保留，不因更新工作流而重算已有研究。

用法保持不变：任一项目首次输入 `$medpaper` 或 `/medpaper pipeline`，之后直接提出修改意见即可。改稿仍在工作流内完成，交付时说明改了哪些、复用了哪些、还有什么真正待办。细节见[医学表达](reference/medical-reader-presentation.md)和[精准返工](reference/rework-routing.md)。

## 1.18 版：原地读数据，控制复现和审阅返工

本版对照 Kiro 1.13 和两份新的脱敏运行复盘，重点解决磁盘占用、重复复现、反复追加分析，以及内部工作记录进入论文的问题。

- **已有数据原地读取。** 用户给了数据位置，就在当前项目登记该位置，Python、R 和完整性检查共用这一引用。默认不复制原始数据，也不用可能回写原件的硬链接冒充独立副本。全量范围、来源哈希、实际记录数仍须核验。
- **复现只处理真正受影响的产物。** 沙箱留在本项目内；本地输入复制有预算，超限就停止并提示改用原地引用，不会抽样或悄悄复制数 GB。新增脚本、无关文档不会迫使全部模型重跑；下游能获得完整上游结果。失败不覆盖旧的有效复现证据。
- **清理只碰本任务的资源。** 正常失败、中断会清理沙箱；强杀后的残留仅在确认归属、主进程和已记录子进程均已结束后处理，不扫公共临时目录，不按进程名称批量杀任务。日志保留在本项目。
- **安装后的引擎有身份检查。** 安装包记录工作流文件的指纹，受管命令遇到文件被改会停止，更新前也会检查。研究项目不能靠改公共工具、核验文件或状态来过关。这是漂移检测，不是假称能越过宿主权限硬拦所有编辑。
- **论文写实际研究，不写内部流水账。** 普通回顾性挖掘默认不在正文、补充方法或投稿信交代“方案未注册”“初始方案为何变化”；内部记录仍保留。真实事后分析、探索性和科学局限必须如实说明。每节写完就检查医学表达，S22 再统一风格。
- **减少同一建议反复询问。** 已由作者明确裁决的可选方法建议，只有建议本身和科学依据均未变化才可沿用原裁决；新证据、实际错误和关键科学问题不能借此跳过。不会把所有审阅建议自动变成新增分析。
- **先判断修改，再花时间排版。** 新增只读的实际修改分类命令；严格相邻重复句可去重，但“数字存在于结果文件”不自动等于无害排版。另修复千位分隔符、正常名词和审批编号的误报，标识符列保留原样。

独立审阅可只写指定的报告文件；如果宿主不允许，父会话原样保存完整报告，不再从其他会话记录中挖取。科学定稿与期刊副本、全套 Word 黑点清理和既有审阅冻结继续保留，不会擅自迁移或重算已有论文。

具体用法与边界见[数据与审阅隔离说明](reference/data-and-review-isolation.md)。

## 1.17 版：吸收完整运行复盘，减少误报和重复劳动

本版核对了 Kiro 1.12 的代码及脱敏运行复盘，只修正 Codex 中实际存在的缺口，既有的临床标签、增量返工和审阅闭环继续使用。

- **减少正常修改被误拦：** 已完成阶段回查不再误判后续审阅文件；表注按实际三线表结构检查，不要求出现特定英文单词，也不把正文单元格的字符限制套到脚注上。
- **分清等待和错误：** 忽略 Office 临时锁文件；工作簿被占用时提示完成保存或关闭 Excel。图的渲染与 QC 按单图互斥，未完成就显示等待，不冒充通过，也不覆盖上一份检查记录。
- **保住原话：** 审核确认与修改理由支持 UTF-8 文件、Base64 传参，确认入库后回读核对；不擅自把乱码猜改成用户批准。
- **减轻续跑负担：** 新增 `wf handoff` 简短交接；四张最长阶段卡改成简明入口，完整操作细节只维护一份、按需读取。未变化的纯检查证据可复用，真实性检查仍须执行。
- **补齐实际输出：** 正确识别横向、纵向及含负值的堆叠柱；源文件支持的“每 1000 份报告”等说明性单位可逐单元格绑定，不能借此豁免研究数字。主稿可按期刊明确要求生成并核查连续行号。
- **避免隐藏回退：** 显示引擎、状态及已完成门控的锁定版本；现代项目升级不再误触早期迁移回退。长任务提供有限心跳，实际失败与完整日志保留。

仍保留你确定的 Word XML 清理、缩写集中管理、独立审阅和科学母版冻结。不新增默认写作代理或每轮全量 Word，也不会按变量名猜统计含义、删除未映射的结果来让稿件表面整洁。

具体命令与边界见[运行可靠性说明](reference/structural-quality.md)。

## 1.16 版：从运行结构补齐临床表述和审阅闭环

对照另一工作流的运行反馈，本版区分了已有能力、实际缺口和不能照搬的建议。

- **实际补齐：** 在原图表计划中共用临床标签词典；不同数据来源的同名内部代码不会被自动当作同一终点。分析变量和数值不被改名或重算。
- **实际补齐：** 新审阅轮次要登记并逐项处置所有可行动意见，包含阅读理解、医学呈现中的意见，不再只处理必改清单。后续审阅默认按实际变化和依赖聚焦，首轮及终审仍保留完整阅读。
- **实际补齐：** 流程图免除坐标轴要求；S07 提前确定可逆的物理展示参数，新图默认按最终尺寸至少 8 pt 规划，期刊明确规则在投稿副本覆盖。不是提前替用户锁定期刊。
- **实际补齐：** 提供只读返工预览；识别投稿文件编号与章节别名，科研数字和否定、方法、结论变化仍受保护。真实科学修正需明确授权后更新对应审核，不自动重跑阶段尾部。
- **实际补齐：** 百分比核对实际分子、分母和比较口径；下游正文、图表不准作为分析输入，避免文字修改触发无关复现。表注长度改为软提醒，不靠拆句满足字符限额。
- **继续保留：** 科学母版与期刊副本分开、展示增量不反复确认、真实来源与独立审阅、增量依赖构建。
- **不盲从：** 不恢复 Word 被禁止的 keepNext/keepLines，不重复堆砌局部缩略语，不强制每轮生成完整 Word，也不把能溯源的新数字自动当作无害排版改动。

完整原理及实际使用见[结构质量说明](reference/structural-quality.md)。这些检查不能替代真实医学判断或证明模型一定读懂了论文。

## 1.15 版：医学读者能看懂的正文、表和图

根据真实运行反馈，把“没有代码残留”进一步提高为“统计含义和医学表达都清楚”。这次只依据用户粘贴的意见提炼普适规则，不宣称核查了未提供的原始论文。

- 主文保留科学定义、统计方法和必要去重说明；底层解析、字符匹配及日志信息按必要性放入补充方法，不机械禁用 R/Python、Firth 回归、Missing 等正常术语。
- 表题、行列标签、混合统计汇总、缺失处理、各分析分母和脚注一起核对。源别模型分别解释，内部步骤编号不能代替医学说明。
- 严格区分患者／报告／记录、点估计／置信界限、零／未拟合／不可估计／无界区间；不得为了好看改变研究含义或把事后规则写成预设。
- 图中临床终点、比较组、箭头、非标准符号和敏感性分析分母必须解释清楚。图注负责看懂图，不复述结果。
- 不为每图每表重复堆缩略语；保留集中管理，同时在读者需要处解释关键终点和统计标记。
- 在原有验收中记录实际医学检查和最终 Word 渲染页，核对表注孤页、图例拆分和交错放置；具体位置遵循期刊，不强制所有图注同页。

代码扫描只提示风险，不自动改文，也不能冒充语义或视觉验收。只重建受影响内容，不新增独立审核轮次或额外审阅材料。详见[医学呈现规则](reference/medical-reader-presentation.md)。

## 1.14 版：先把科学内容做对，再写作和投稿

- 调整为先定表、再定图、再写 Results，交叉核对不再承担预设返工。
- 分析前明确变量口径、主要比较和多重性；结果后核对十条原始记录（不足十条则全查），不代替全量分析。
- 方法文献在写 Methods 前核验；既往研究数字可引用，但须绑定真实原文，关闭自由填数旁路。
- 声明根据研究设计、每个数据来源及官方政策评估生成；只有真正缺失的信息才询问。不会推定伦理批准或知情同意豁免。
- 检索看论证角色；45–60 篇仅为组全文后的参考体检，入库未引用的文献需要说明理由。写作额度和默认图注长度均为软提示，定刊后才按明确上限适配。
- 选刊后立即复核图表组合；不改科学母版，只改期刊版本。
- 外部第三方审阅副本仅按明确请求生成；独立只读审阅与冻结保留。数字、分组及结论强度意见不能由被审者按偏好关闭。
- 新版本确认统一为“我确认这一版”，绑定实际当前文件，而不猜测“继续”“OK”的含义。

执行细节见 [质量与执行规则](reference/quality-before-writing.md)。

## 1.13 版：迁移 Kiro 1.9 的冻结后修订与期刊驱动构建

本版依据您维护的 Kiro 1.9.0（2026-10-17，提交 `f806de6`）适配，重点是让正常改格式不再触发一轮科学返工。

- **已确认版本按实际内容分级。** 拼写、空白、受控标题／数字展示和可证明的排版修改，完成局部校验后记录展示增量，汇报一次，不自动回 S19、不重开子代理审阅、不重复要求确认。初次审核、用户主动要求再审，以及真正改变科学内容，仍走相应审阅。
- **不把“数字一样”当成“科学一样”。** 还核对引用、单元格对应、单位、时间、比较、方向、否定词和方法主张；含义不能自动确认的改写，由主代理实际读前后文并留下绑定版本的判断。旧冻结、旧独立报告和旧发布文件保留，新上传字节有独立只读版本及增量来源，不偷换历史。
- **期刊字段真正驱动成稿。** 正文标题、关键词数量／分隔、盲审、英美拼写及数字格式进入构建输入；源 Markdown 保持规范结构，最终 Word 按实际标题统计。检查补充材料及隐藏元数据中的作者信息，不只检查正文。
- **相同内容不为时间戳返工。** DOCX/XLSX、受管 R 的 PDF/TIFF 输出规范化元数据；内容比较不随 Word 修改时间变化，也不会删掉临床日期、真实作者或任意 JSON 日期字段。参考文献格式补丁只作用于论文的本地 CSL，不改共享样式及真实文献库。
- **将问题前移。** 编号按首次引用检查，表题对照实际工作表，显式分面板不得漏引；正文保持医学论文连贯叙述。新分析可一次导出二分类两类及分组、缺失计数，避免后期临时算数。新增清单 Word 和联系表工具，但仅在期刊实际要求时生成清单。
- **升级与作者终稿都有明确边界。** 已完成阶段的新增展示门禁保留版本锁，`wf migrate` 才主动采用；真实性门禁不因此跳过。作者明确选择在副本手工完成投稿细节时，可走“作者终稿副本”交付，原稿及独立审阅保留；这不冒充新的独立通过，也不代表已向期刊提交。

仍不默认要求数据挖掘研究公开注册，不预先铺设报告清单，不恢复固定文献数／图数／字数门槛。不同期刊的改动仍留在期刊副本，只有明确针对科学母稿的、含义不变的修订才可使用母稿展示增量。完整规则见 `reference/content-aware-amendments.md`。

## 1.12 版：迁移 Kiro 最新审阅方式与 Word 表格改进

根据用户维护的 Kiro 1.8.1（2026-10-17，提交 `1c49c93`）适配，不再沿用早期“每版审核 ZIP”的约定。安装更新用的工作流 ZIP 不受影响。

- **取消审核 ZIP，改为子代理审阅轮次。** S18 启动第一轮科学审阅，S19 由主代理判断意见并在工作流内主动修正可安全解决的问题。S24 对真实投稿文件使用同样方式。每轮集中汇报改了什么、哪些未采纳及原因，只问一次“是否再审一轮；无需继续请回复无需继续审阅”。用户仍可亲自看文件或直接提出修改。
- **确认绑定版本，局部返工。** 新增、删除和实际依赖都纳入轮次，材料变化不能套用旧确认。未知依赖从严扩大审阅，不假装无需检查；不重跑无关数据和分析。涉及科学事实的修改仍回到真实来源，不凭审阅意见编造数据或文献。
- **原生 Word 三线表。** 指定真实 XLSX 工作表、表头和数据范围后生成可编辑表格，表题和表注在表格外，保留合并表头。每表独立分页，按宽度自动或明确指定横竖版，清理格式后不再被强行改回竖版。默认连续页码；期刊明确规则优先。
- **参考文献编号后的空白统一。** 数字编号后默认一个普通空格，不自动插入 TAB 或悬挂缩进；期刊明确要求时才改。编号标点和真实文献信息不因此改变。
- **让审阅者能读到实际内容。** 为 DOCX/XLSX 生成绑定原文件版本的完整本地文本副本，同时仍要看真实图片和渲染页面；文本提取不冒充视觉审核。
- **核对实际文件，不只勾选清单。** 最终上传文件、Word 格式、原生三线表、页码及实际 Word 投稿字段形成可复用测量结果，文件或规则变了才重新测量；自动测量不替代人工式视觉判断。

科学母稿与期刊副本仍隔离；最终用户确认、冻结和 S25 独立读者／编辑／合规终审仍保留。旧项目的审核 ZIP 和旧冻结不删除、不改写，已有有效记录继续按原覆盖验证。新项目不再依赖审核 ZIP。工具不能证明子代理真的理解医学，更不能证明不存在错误，执行器仍必须实际委派、读文看图并处理发现。

## 1.11 版：先对标真实论文，再主动完成专业交付

取消统一的文献库、章节引用数、章节字数和主图表数量门槛。不是把要求降下来，而是把“足够”的依据改为当前项目的科学问题、真正读过的相近全文和目标期刊的明确规定。

- **写作前对标。** S07 比较主题、设计和分析相近的已发表全文，观察医学结构、文献承担的论证作用、主补图表的分工，形成当前项目自己的计划，然后才写 Methods、制作正式图表。只有摘要或一个“已对标”标记不能通过。
- **覆盖优先，不凑数量。** 文献库规模、正文实际引用、章节引用和补充引用分别统计。关键研究和方法依据必须落实到实际引用段落；超出预计范围需要解释覆盖是否充分，不能填无关引用或事后降低范围让稿件过关。
- **每个图表都有具体作用。** 明确它回答的问题、人群与比较、指标与分母、主文或补充位置、与其他图表的区别及容易误解之处。复制展示理由或检查说明会被拦下；医学含义仍须实际看图判断。
- **选刊后补同刊对照。** S20 再读同刊相近全文，确定期刊副本的组织与展示方式。新增的风格对标资料进入公共文献缓存，不改已经冻结的科研稿或正文参考文献库。期刊明确要求的上限继续严格执行。
- **执行器先验收再交付。** S17 对完整科学稿、S22 对投稿副本的制作前内容、S23 对实际上传文件进行主动验收。文字、图表或文件发生变化，旧验收失效。用户主要作作者判断和进一步完善，不负责发现常规缺漏。
- **保留增量工作。** 不增加阶段、独立审核智能体或用户停点；复用已经读过的有效材料，仍按真实依赖局部返工。1.10 的组合来源、合法迁移、快照和最终 Word 处理链继续有效。

自动检查能验证来源、覆盖记录、文件对应和版本，不能证明 AI 真正理解医学。执行器必须读全文、看实际图表并说明具体发现，已有的独立审核与用户确认也不取消。旧项目缺失的对标证据应在局部修改轮次中补齐，不能为升级而重做研究，也不能伪称过去已经读过。新的科学冻结绑定对标决策；旧冻结仍按原来的覆盖验证，不因为新增后台证据而失效，但科学稿件发生变化依然会阻断。

## 1.10 版：按实际来源和变更验证，不为正常排版整轮返工

这次处理实际运行中的来源错配、依赖遗漏和重复检查。25 个阶段与科学冻结、人工确认继续保留，没有新增注册或预置报告清单。

- **组合稿件不再被默认来源误挡。** Word 构建记录实际入口、所有已声明输入、参数及内容/文件指纹；投稿基线优先使用真实组合源，而不是按“正文”“补充材料”的角色猜一个文件。自定义脚本仍须声明真实依赖，不能伪造构建凭据。
- **新发现的依赖可在本轮补充。** 不用重写原反馈或重开整轮。“修改过”和“检查过但保持不变”分别记录，正确文件不必为门禁凑修改。变更输入、规则或配置会使旧检查失效；完全相同的本轮检查可复用，关闭轮次主要核对凭据和最终漂移。
- **期刊重组不等于改科研结论。** 期刊有自己的图表规划。搬到补充材料、调整图号等须记录实际来源与去向，并在整个稿件包核对数字、P 值、引用和显示项。真正改变科学事实仍要科学返工和重新确认，不能用“排版迁移”逃过。
- **限制来自明确的文章类型和字段。** 不再从指南全文随便抓数字当作上限；强制、允许、推荐和未规定分开记录，未规定用空值。最后比较实际 Word。Discussion 不默认给每个论点加标题，声明顺序及主补图注按实际期刊要求处理。
- **Word 有统一收尾顺序。** 构建后必要的排版修复，再清理格式、最终渲染，最后绑定基线与投稿字段。页眉、脚注和表格中的文字变化也会被检测；单纯空白、分页编号变化不当作科学改动。任务进程有超时和完整本地日志，失败保留原产物，不关闭无关 Office 进程。
- **只限制展示，不截断研究。** 事实命令默认给有限预览，完整结果保存在本地，并可按事实、字段和分页查询。数据获取仍是全量，必要的方法、分析、真实性和人工审查没有减少。

目前自动记录覆盖受管构建器，不是监控任意程序全部文件读取；外部脚本和 Office 自动化需要对应的有超时、明确资源所有权的适配。内容指纹也不能替代对语义、医学解释和版面可读性的检查。旧研究资料不因升级而重写；旧凭据不齐时补真实依赖，不自动宣称验证通过。

## 1.9.1 版：不默认注册，不预先制作报告清单

数据库挖掘、公开数据二次分析、回顾性研究及本中心既有临床数据研究，默认不要求 OSF 或其他公开平台注册。工作流保留本地分析方案、必要的方法和伦理要求，但不会把“写了方案”当成“必须公开注册”，不会索要账号、注册号或为了门禁补造注册文件。

系统综述/Meta 分析或真正的前瞻性干预试验，才在方案阶段按具体研究类型核实注册要求及时间条件；建议不等于强制，也不把已完成研究倒写成事前注册。[ICMJE 明确区分干预试验与纯观察性研究](https://www.icmje.org/about-icmje/faqs/clinical-trials-registration/)，综述注册条件则按[注册平台的现行规定](https://www.crd.york.ac.uk/PROSPERO/help/forjournals)判断。此处来源核对日期：2026-10-08。

研究和写作阶段不选择报告规范、不下载或填写报告清单、不按清单条目堆砌 Methods，也不因此自动增加流程图。到 S20 选定投稿杂志后，只有官方指南明确要求，才在 S23 的期刊投稿副本中补充指定清单；不修改已经确认冻结的科研母稿。期刊未要求就不生成。投稿包的简短文件核对表仍保留，它只用于核对实际上传材料，不是科研报告清单。

旧研究资料和已完成的人工修改保留；升级只改工作流引擎，不为了删掉旧标题或历史字段而把研究返工一遍。

## 1.9 版：吸收 Kiro 版的有效设计，不增加整轮返工

对照 `medpaper-kiro-workflow` 的实现后，保留现有的医学表达、科学冻结、人工审核与局部返工，新增四项实际能力：

- **结果留下真实运行来源。** Python 和 R 的结果写入器记录真实执行脚本、完整输入文件、环境版本与随机种子；环境里的版本号、种子等不计入论文的科学数值来源。R 输出保留 17 位有效数字，不按显示精度储存。
- **只复现该复现的分析。** 收敛后，在隔离目录中用完整的已声明输入复现指定结果。后续写作检查比对结果和来源，不重复计算。只改正文措辞或图的排版，不重跑模型；科学修改只处理对应生产脚本和真正的依赖。旧结果不伪装成已复现，下一次科学修改时从原分析脚本接入新接口。
- **下载的是不是那篇文章，也要检查。** XML/HTML 核对文章自身元数据，而不是在参考文献中搜到 DOI 就算成功。错文献拒绝替换原文件；PDF 或身份不确定的全文需要读者明确确认对应文章，不能自动贴上“已核验”。原有 PubMed 元数据验证仍然保留。
- **R 常见图不必每次从零编写。** 增加森林图、ROC 和校准图的基础配方，只消费已确认的结果，不在作图时重新拟合、不静默删除缺失数据。复杂图仍按医学研究实际需求设计，不能只套模板。

同时，写作规范的修改也会使旧检查缓存失效，避免规则改了却沿用旧的“通过”。详细运行接口按阶段加载，不扩大日常对话上下文。

未照搬的设计包括：按文件名重跑全部分析、强制安装全部医学 R 包、Kiro 专用 IDE hook、全局“当前论文”切换、仅凭章节标题判断报告清单已经满足，以及把 PDF 任意位置出现的 DOI 当成文章身份。它们可能增加耗时、误操作或假通过。报告清单仅在选定期刊明确要求时按当前官方表格处理，不使用预设目录。

这次升级不改动正在运行的研究资料，不增加阶段，也不承诺未经实测的 token 降幅。严格复现证明可重复性，不等于方法一定正确或一定能发表；科学审查、真实看图和人工确认不省略。

## 1.8 版：医学作图默认用 R，分析按方法选工具

数据获取、清洗和大文件处理仍可用 Python；生存分析、缺失值处理、混合模型、医学回归验证或 Meta 分析，应先考虑符合方法需求的成熟 R 实现，而不是让 AI 凡事默认 Python。并不是所有分析都必须换成 R，也不重复计算已确认的结果。

新医学统计图默认用 R，保留 `.R` 源文件，统一主题、尺寸和布局，生成矢量 PDF 与 PNG。工作流已有实际可运行的 R 渲染通道，能检查来源、字体、线宽、部分文字碰撞和必要图形元素；渲染失败保留原图。改某张图的字号或图例，只改对应 R 源文件并重绘该图，不重跑数据和模型。

R 图不需要转成 Matplotlib，也不调用仅适用于 Matplotlib 的 Tavotto。已确认的 Python 图保留，确有必要使用 Python 时记明原因。复杂原生 R 图形需要对应适配与目视检查，未知检查项不会伪装成通过。缺少 R 包时处理依赖，不悄悄改回 Python。自动检查始终不能替代真正看图。

## 1.7 版：减少重复劳动，不降低科学检查

- **数字要对得上具体发现。** Results、摘要及表格的数值绑定到实际分析结果中的具体结局和上下文，不再只检查“某个数字是否在库里出现过”。正负号、小数、P 值阈值和表格单元格也检查。后台绑定不会印进论文；医学解释仍由科学审查和读者审查判断。
- **正常刷新证据不等于重写论文。** 文献核验记录或证据缓存更新，不再被旧修改轮次永久锁住；相关真实性检查仍须通过。正文、结果、图表和用户确认的上传文件继续严格保护。
- **刚通过的本地检查可以复用。** `check` 后推进阶段，只有依赖文件、规则和配置完全匹配且在两分钟内的白名单检查才复用。在线文献、数据完整性、用户确认和最终冻结检查不使用这个缓存。输入不齐时先停止昂贵检查，也不能用 `--force` 越过未执行的门禁。
- **改一张图的规划，不默认重画全部图。** 修改轮次保存原规划。修改后运行 `rework.py refresh`，仅条目内变化可缩小到相关图表；共用设置变化、清单增删重排或依赖证据不足仍保守复核。受影响列表是复核范围，不是全部重写的命令。
- **少重复读历史。** 返工状态默认显示待办，完整历史保留在 `status --full`；科学事实可直接读取精简的来源解析结果。入口技能只保留路由和关键约束，按阶段读取详细规则。

已有项目不会在安装时重写研究资料。旧项目如果缺少新的结果绑定，需要从真实分析输出补齐，不能把稿件中的数字倒填为证据；涉及已冻结科学内容的变化仍需正常复核确认。此次不承诺固定 token 或时间降幅，是否节省取决于修改类型和文件规模。

## 1.6 版：让读者看得懂，让修改只影响该改的部分

过去虽然要求“只重建相关文件”，返工状态仍会跳到前面的阶段。现在，新建修改轮次会停留在 S19 或 S24，调用相关阶段的规则检查，不再把后面所有阶段清空重跑。

- **改之前明确三个范围：** 要修改或重建哪些文件，只需复核哪些内容，哪些已有成果保持不变。改图 2 的字号不应重新分析数据、重做图 1 或重建文献库。共用脚本或缺少依赖记录时采取保守检查，不假定彼此无关。
- **范围不只是一句提示词。** 常用文稿、Word、图、表生成器会拦截超范围写入；结束时还会检查是否动了无关文件。必须实际运行检查，不能只写一句“已验证”关闭任务。
- **医学表达提前确定。** S07 不只参考图表数量，还看真实医学论文的临床叙事、标签、分母、单位和图注。每张图表先明确研究谁、比较什么、度量什么、如何解释及不能推断什么；后台技术字段不印进正文或图表。
- **减少预先就能避免的返工。** 缩写如何解释在做表前决定，S17 负责检查和组装。Results 围绕临床问题组织，不按代码运行顺序写分析报告；必要的阴性结果、模型性能和科学限制仍保留。
- **独立审查真图真表。** S18 收到实际渲染图片，而不只是图注，并说明读者哪里可能看不懂。文件哈希只证明版本，不能替代医学判断。
- **晚期科学纠错仍须你确认。** 若修改涉及已冻结的科学内容，先在 S19 修正并重新请你批准；之后回到 S24 只同步受影响的期刊副本及上传文件。其他阶段历史和无关人工修改保留。

你可以直接对话提出修改意见，不必每句话都输入 `$medpaper`。AI 必须把修改记入工作流，并告诉你改了什么、复核了什么、哪些没动。明确说“按这些意见修改”后，不会再要求重复确认才开始。节省的是重复理解、无关读取和重复重建，不是减少数据、分析或质量检查。

升级不改动正在运行的研究文件。旧版未完成修改轮次保留原门禁完成；新开的轮次使用 1.6 局部返工。

## 1.5 版如何减少实际运行中的返工

本次优化保留全部科学质量检查，主要改变“什么时候确认内容、什么时候生成昂贵文件”。

- **写作前先确认科学规则和临床主线。** S06 固定研究范围、分母、结局、缺失与去重、模型、敏感性分析和验证边界，并用四句话说明临床问题、主要发现、意义与不能得出的结论。后来改动这些来源会使写作检查失效，必须从对应科学阶段处理。
- **图表先做能读懂的低成本原型。** S07 先看 Markdown 表格和预览图，确认名称、分母、单位、类别重叠、图例及布局。每张主表、补充表和图都记录实际读者解释。AI 模拟读者会如实标注，不能冒充临床专家。S10/S11 再沿用通过检查的方案制作。
- **一轮反馈收齐后统一改。** 你可以连续给意见，AI 先记录，待你表示本轮结束或明确要求开始修改再统一处理。完整的“按这些意见修改”本身就是执行指令，无须多问一次。重复意见不会重复登记；修改轮数不限。
- **按文件关系重建。** 例如只改题页联系方式不会重跑统计，某张图改字号不会重建文献库。两次完整构建后若仍有问题，转为查明原因并定向修复，不能因此停止修改或省略检查。
- **投稿信息来自最终文件。** 按期刊确定实际上传清单，最终 DOCX 中提取标题、摘要、关键词和字数，并从统一作者事实表生成门户信息。计数方法会明确显示；若期刊指定 Word 自身口径，仍以 Word 核对为准。
- **上传文件和后台证据分开。** 用户确认后，实际上传文件复制到独立只读发布目录。缓存、日志、渲染页和回执更新不再迫使你重新确认相同稿件。任何真实上传文件变化仍须重新确认；期刊规则变化须重新核对对应要求。
- **文献身份检查更完整。** PMID、DOI、PMCID 和完整有序作者列表一起核对，机构作者和姓氏粒子按真实姓名保留。文献真实与论述得到支持是两件事，正文依据仍需阅读核实。
- **状态恢复更轻。** 默认状态只显示当前阶段、缺失项、反馈状态和下一步，不会每次重复读取整套规则或访问 PubMed。未变文献可短时复用带哈希的独立在线核验结果；身份变化或证据过期仍必须重新获取。

正文和投稿稿的隔离、明确审核确认以及 S18/S25 独立审阅均保留；S19/S24 按 1.12 的子代理轮次处理，不生成审核 ZIP。独立子代理不可用时只能交付标明性质的本地初查，审阅保持待完成，不能把主代理检查伪装成独立通过。

新项目直接执行新规则。旧项目的文件会保留；遇到新增检查时，AI 应依据已有真实证据补齐分析规则、临床主线、图表原型或投稿清单，必要时按原流程返工。旧版最终冻结须在 S24 确认后生成新的只读发布版本。不会为了升级而删除研究文件或自动宣布旧文件已通过新检查。

## 这套工作流解决什么问题

医学论文真正困难的部分不是生成文字，而是让研究问题、数据、统计分析、文献、图表、正文和投稿文件彼此一致，并且符合目标期刊的要求。这个工作流用分阶段推进和自动检查来降低以下常见风险：

- 研究选题已经高度饱和，做完后缺乏发表价值；
- 数据源明明可全量获取，AI 却为省时间、上下文或算力只取前 N 条、抽样或漏翻页；
- 引用、DOI、PMID、期刊名或年份由 AI 凭记忆生成；
- 正文中的数字没有分析结果作为来源，或表图与正文对不上；
- Methods 过长，把敏感性分析、实现细节等全部堆进主文；
- 图注重复 Results，缩写到处重复，表格和图片不像医学期刊文章；
- 作者信息过早介入，打断科学内容的形成；
- Word 文件字体、字号、行距、颜色、标题层级或超链接不符合期刊要求；
- 投稿包缺文件，标题、作者、图表编号、补充材料和声明跨文件不一致；
- AI 生成并不存在或未经用户确认的伦理、基金、利益冲突或作者信息。

工作流的目标是：在保证研究有效性和材料一致性的前提下，优先寻找真实、当前、合规且接受概率较高的 SCIE 期刊。Q3、Q4 和低影响因子期刊完全可以作为合理目标；不会为了影响因子牺牲匹配度和现实接受概率。

## 适合与不适合的情况

适合用于临床队列、回顾性研究、真实世界研究、数据库研究、生存分析、预测模型、组学研究及其他可形成医学论文的项目，也可从已有数据、已有分析或半成品论文继续推进。

它不适合替代研究者的伦理责任、临床判断和最终署名确认；也不能把数据本身不支持的结论“包装”成可发表结果。若关键设计、数据质量或统计有效性存在硬伤，流程会给出 `PIVOT`（调整）或 `STOP`（停止），而不是继续生成投稿文件。

## 核心处理逻辑

整个流程遵循一条依赖链：

```text
研究问题 → 发表可行性 → 方案 → 数据 → 分析结果
        → 图表计划 → Methods/Results → 实际图表 → 一致性校验
        → 参考文献 → Introduction/Discussion → 完整论文
        → 独立审查 → 人工修改 → 科学母稿冻结 → 期刊选择 → 期刊专属整合副本 → 投稿包
        → 人工最终确认 → 独立投稿审查
```

每个阶段都声明自己的输入、输出和通过条件。只有当前阶段的必需文件存在并通过检查后，流程才会进入下一阶段。这样可以避免论文先写完、最后才发现数据、文献或图表无法支持正文。

用户审阅后提出的修改也不会脱离流程。系统先判断修改由哪个阶段负责，在当前审核节点调用其规则：例如 Methods 由 S08 负责，Results 文字由 S09 负责，统计结果由 S05 负责，Discussion 由 S16 负责。修改首先落到分节 Markdown、分析结果、表格或图片等来源文件，再重新组装依赖项；不会孤立修改 `full_manuscript.md`。

反复改稿有两个固定入口：S19 用于科学内容和完整论文的审核；S24 用于期刊专属 Word、投稿文件和跨文件一致性审核。反馈的原话、解释、修改项、来源和验收标准保存为修订轮次，依次调用负责阶段的规则，不清空后续阶段。新增反馈可并入当前轮次；全部修改项完成且真实检查通过才能关闭。轮次数量没有上限。

S19 明确结束审核后，工作流把期刊无关的科学母稿、分析结果、已验证参考文献、表格、图片和批准的审阅轮次／报告冻结，不再生成或绑定审核 ZIP。S20 以后只编辑派生的 `08_submission/integration/`，期刊要求的摘要结构、篇幅、措辞、标题页、声明和上传格式都保留在这一层。更换期刊仍从同一冻结母稿派生，不来回覆盖已经确认的科学稿。

如果方法、分析、结果或科学解释需要真正修改，原 S19 确认失效；按来源局部返工、重新组装、完成新审阅轮次并取得用户确认后，再冻结科学母稿。只更新受影响的投稿消费者，不重放整个阶段链。

这种设计不会用“少读、少改、少检查”换取 token。流程在上下文压缩后从磁盘上的修订状态恢复，不需要反复重读整段聊天；只读取受影响的来源文件，重建真正依赖它们的产物，并复用未变化且哈希仍一致的证据。所有受影响的分析、数值溯源、引用、图表、Word 渲染、人工确认和独立审查仍照常执行。token、上下文、时间或计算成本都不能成为遗漏修改项、缩小研究范围或跳过质量门禁的理由。

贯穿全流程的规则包括：

1. 数据获取默认覆盖 S03 已定义的完整研究数据范围。每个来源都要保存源端总数、实际接收数、末页/游标证据及原始文件哈希；不能为省时间、token、下载量或算力自行抽样、只取前 N 条、限制页数或缩短日期范围。
2. 文献搜索工具可以发现候选论文，但正式引用必须重新获取并验证元数据。
3. 正文中的统计数字必须先存在于代码生成的机器可读结果中，不能在写作时心算或补造。
4. 润色只允许修改表达，不允许悄悄改变数字、引文、图表引用或结论强度。
5. 患者级数据、个人信息、凭据和密钥未经明确授权不得上传到外部服务。
6. ImageGen 可参与图片的视觉检查和改进建议，但不能代替由数据和代码生成科研图，也不能绕过数值核对。
7. 工作流不会自行撰写或加入 AI 使用声明；如期刊要求，只把它记录为由用户决定的合规事项。

## 25 个阶段分别做什么

### 第一部分：确定研究是否值得做

#### S01｜整理研究想法

把自然语言想法整理成结构化研究问题，包括研究设计、人群、暴露或干预、对照、结局、预期创新点、候选数据源和待确认问题。此阶段需要用户提供真实研究意图，但不会询问作者、单位等投稿信息。

输出：结构化研究想法和贯穿项目的研究笔记。

#### S02｜第一次发表可行性判断

使用真实文献检索了解已有研究、研究空白和主题饱和度，并记录检索过程。判断该问题是否值得继续：`GO` 表示继续，`PIVOT` 表示调整问题或设计，`STOP` 表示当前条件下不宜投入更多工作。

输出：可行性报告、检索记录和第一次 go/no-go 决策。

#### S03｜形成初版研究方案

明确研究目的、设计、人群和纳排标准、变量、主要统计计划、样本量或精度考虑以及伦理要求；不预选报告清单，不默认要求公开注册。同时定义需要获取的完整数据范围、数据从哪里来、精确查询与过滤条件、如何翻完全部页面、如何证明源端总数与实际接收数一致。

输出：初版 protocol 和数据获取计划。

### 第二部分：让数据和方法形成可靠的科学故事

#### S04｜获取并登记数据

保存原始数据，建立变量字典和来源记录，使用代码生成数据集概要和缺失情况。原始数据视为不可随意修改，清洗后的数据与生成过程分开保存。

这一阶段不再以“raw 文件夹里有文件”作为完成标准。`acquisition_manifest.json` 会逐个来源核对：源端总数证据、请求数、接收数、原始载荷计数、是否到达最后一页/空游标、全部原始文件与获取代码的 SHA-256，以及接收记录到分析数据行数的排除/合并关系。获取代码中的 `LIMIT`、`TOP`、`head()`、`sample()`、前 N 条切片和固定页数等常见偷懒旁路会被阻断，且不能用 `--force` 绕过。

允许两种不等于“偷懒抽样”的情况：一是协议在看数据前就规定、并经用户明确同意的科学抽样设计，此时仍须获取该设计样本的全部记录；二是只用于测试连通性或字段的小型 pilot，但 pilot 不得用于分析，且 S04 结束前必须继续完成全量获取。若外部来源确实限制访问，AI 必须先向用户说明范围和偏倚，只有用户明确授权后才能用完整的“可访问子集”继续。

输出：原始/衍生数据、获取代码、全量获取清单、codebook、provenance 和数据集概要。

#### S05｜方法调研与探索性分析

结合同类研究的方法进行检索，运行分析代码，检查数据能够回答什么问题、哪些结果稳定、哪些地方需要调整。此时不急于制作正式图片，避免在分析尚未收敛时浪费排版工作。

输出：分析代码、机器可读结果、分析日志、方法调研和关键发现笔记。

#### S06｜冻结最终方案并再次判断可发表性

根据真实数据和分析结果修订方案，说明相对初版的偏离及理由，并进行第二次 go/no-go 判断。只有分析已经收敛且研究仍具现实发表价值，才进入写作和正式制图。

输出：最终 protocol、方案差异记录和第二次决策。

### 第三部分：先规划正文需要的证据，再写作

#### S07｜规划表格、图片和图注

参考同类型医学论文，确定主表、补充表、主图、补充图及补充文件的合理数量和作用。图注只负责解释设计、分组、符号、统计标记和阅读方法，不复述 Results 中的结果。

输出：图表计划、同类文章基准、表题和图注草稿。

#### S08｜撰写 Methods

采用医学 SCI 论文常见而灵活的骨架：研究设计与场景、研究对象及纳排标准、暴露/干预和变量、结局、数据来源与质量控制、统计分析、伦理。只保留理解和复现研究所必需的内容，通常以 Statistical analysis 结束。

若敏感性分析、亚组定义、算法参数、复杂实验步骤或实现细节会让主文过长，则写入独立的“补充方法”，主文只做简洁说明并指向补充材料。补充方法只保留叙述性方法内容，不嵌入表格，也不保留 Markdown 的 `---`、`***`、`___` 等长横线；所有补充表移至 S10 生成的独立三线表工作簿。具体小标题会随研究设计调整，不强迫所有研究套用同一模板。

输出：Methods；必要时另有 supplementary Methods。

#### S09｜撰写 Results

只根据已经运行并保存的分析结果写作，按科学问题组织叙述，引用已经规划的表和图。所有数字必须能回溯到结果文件，不在文字中临时计算。

输出：Results 初稿。

### 第四部分：生成并核对读者真正看到的表和图

#### S10｜制作医学期刊表格

从分析结果生成读者可读的三线表。主表与补充表分别组织，检查数值来源、表题、脚注、缩写、格式和可读性，并进行实际视觉检查。

输出：XLSX 表格、生成脚本和表格清单。

#### S11｜制作医学期刊图片

由分析代码生成矢量 PDF 和 PNG 预览；期刊确实要求时再导出 TIFF 等科研图片，检查尺寸、分辨率、字体、线条、颜色、面板标识和图注对应关系。先做确定性的技术检查，再看渲染后的实际图片；发现问题则修改代码并重新生成。

输出：图片、生成代码、质量检查报告和最终图注。

#### S12｜正文、数字、表格和图片对账

逐项确认 Methods 和 Results 中的分析、数值、表图编号与实际产物一致，确保没有未引用的图表、错误的编号或跨文件数值冲突。

输出：一致性核对记录。

### 第五部分：建立可信文献基础并完成正文

#### S13｜建立已验证参考文献库

文献库大小根据真实全文对标和本项目的论证需要确定，不设统一的数量门槛。每条正式文献必须由内置 `tools/pubmed/verify.py` 发起一次新的 PubMed EFetch，并把原始 XML、XML 的 SHA-256、解析后记录指纹和当时的 `library.json` 哈希绑定在一起。门禁会重新解析 XML 并逐项复算 PMID、DOI、PMCID、题名、完整有序作者、期刊、年份和摘要；S13 和 S25 必须另行实时访问 PubMed 核对；中间关口只在全部身份信息、原始 XML 哈希均一致且距独立核验不超过 24 小时时复用证据，否则重新联网，失败则阻断。`verified: true` 只是状态字段，单独存在没有任何证明力。BibTeX、RIS 和内部文献库也必须一致。

引用真实性门禁属于不可豁免门禁：即使使用 `wf advance --force` 也不能通过。任何临时脚本、手写 JSON、伪造 DOI，或者为了消除 Pandoc 警告而直接修改 `library.json`、`verified.json`、`refs.bib`、`refs.ris`，都会因缺失或不匹配的原始证据、文件哈希或实时 PubMed 结果而失败。正确处理方式只能是检索真实论文并替换引用，或者删除没有真实来源支持的引用。

输出：已验证文献库、BibTeX 和 RIS 文件。

#### S14｜撰写 Introduction

从临床或科学背景推进到当前知识缺口，再落到本研究目的。引用只来自已验证文献库，避免泛泛堆砌背景或夸大创新性。

输出：Introduction。

#### S15｜深读支撑 Discussion 的核心论文

在合法开放获取或用户授权的路径下，选取约 5 篇最关键论文进行全文阅读和结构化笔记。仅有搜索摘要而未获得全文时，不假装已经深读。

输出：核心论文深读索引和笔记。

#### S16｜撰写 Discussion

解释主要发现，与核心文献比较，讨论可能机制、临床或研究意义、优势和局限，并给出与数据相称的结论。避免重复 Results，也避免把关联写成因果。

输出：Discussion。

### 第六部分：组装全文并先做一次独立审查

#### S17｜自动选题目并组装完整论文

根据研究问题和实际结果自动选择最准确、最具可读性的题目，不要求用户先从多个题目中选择。随后生成摘要和 3–6 个关键词，并按医学论文顺序组装 `full_manuscript.md`。

关键词位于摘要之后，只使用逗号分隔，不使用 `/`、`;`、`&` 等混杂符号。完整稿包含明确的 References 标题，并在末尾保留简洁 Figure legends。若表图缩写很多，则统一放在 Declarations and Statements 的 Abbreviations 部分，避免在每个图注和表格中重复。

输出：题目、摘要、关键词、声明/缩写区和完整论文 Markdown。

#### S18｜独立子代理审查可发表性

冻结完整论文、补充方法和表格，交给一个只读的独立子代理审查。它不参与改稿，只判断研究是否已具备在合法当前 SCIE 期刊发表的基本条件，并区分致命设计问题与可修正的表达或报告问题。

审查结果为：`READY`（可进入人工审核）、`REVISE`（修正后有发表可能）或 `NOT_READY`（仍有实质性障碍）。判断标准包含科学有效性、报告完整性、方法长度、表格与补充材料一致性、结论强度及现实期刊层级。

输出：独立可发表性审查报告。

#### S19｜用户审核科学内容

把完整论文、补充方法、全部表格和独立审查报告一次性交给用户。用户可修改内容；若修改涉及分析，必须回到分析来源并重新生成依赖项，不能只在正文中改数字。

这是主要的反复改稿节点。用户可以连续提出多批意见，不必每次重新输入 `$medpaper`。流程会为每批意见建立持久化修订轮次，逐项记录验收条件，并按最早受影响阶段返工；回到 S19 后逐项核验、关闭该轮，再把新版本交给用户继续审核。上下文即使被压缩，也从修订状态文件继续，不会靠残缺的聊天记忆猜测。

S19 不再生成审核 ZIP。第一轮承接 S18 的独立子代理报告；主代理在工作流内判断并主动修正安全可修的问题，完成真实局部校验，集中给出修改、未采纳原因和全文、补充方法、表图、参考文献及报告的准确位置。你仍可自行看稿或直接补充意见。

每轮只问“是否再进行一轮子代理审阅？若无需继续审阅，请回复‘无需继续审阅’”。要求再审就开启下一轮，重点看变化及其关联；明确无需继续才记录绑定当前轮次与文件的 `NO_FURTHER_REVIEW`。沉默、致谢或泛指“继续”不代替确认。S24 投稿包也使用这一方式，确认后才冻结并进入 S25 终审。

收到这项明确确认后，流程立即生成 `scientific_master_freeze.json`。冻结对象是用户刚审核通过的期刊无关科学版本；后续任何期刊均从它派生，不直接覆盖它。

只有用户明确确认科学版本可以继续后，才开始选择期刊。此时仍不询问作者、单位、ORCID、基金或通讯信息。

输出：人工审核记录和确认。

### 第七部分：匹配期刊并制作投稿文件

#### S20｜选择现实可投的 SCIE 期刊

依据用户确认后的论文，查找近期发表过相近主题、设计和研究规模的期刊。候选期刊必须当前被 SCIE 收录、具有当前 JCR 分区，并且没有有效的预警、退稿诚信风险或重大出版质量问题。

工作流给出候选列表和退稿后的备选顺序，优先考虑研究匹配度和接受概率，而不是机械追求高影响因子。用户最终选择期刊后，流程保存官方投稿指南、冻结 Word 格式规则，并从 S19 科学冻结创建 `08_submission/integration/` 期刊专属副本。

输出：期刊候选、目标期刊信息、官方指南摘要、DOCX 样式配置和期刊整合工作区。

#### S21｜最后才收集作者与行政信息

在科学内容和目标期刊都确定后，一次性向用户询问作者顺序、单位、ORCID、通讯作者、基金、利益冲突、伦理/知情同意、数据可用性、贡献声明等。缺失信息不会由 AI 猜测。

若期刊要求 title page 报告参考文献数量，流程会按完整正文中实际出现的、去重后的 citekey 自动计算并校准；不会把候选文献库总数误写成正文引用数。期刊未要求时，不会自行添加这一字段。

输出：作者信息，以及位于期刊整合层中的 title page 和期刊所需声明；不会向冻结母稿写入行政信息。

#### S22｜按目标期刊进行事实不变的润色

在 `08_submission/integration/` 中调整英文、摘要结构、允许的小标题、拼写体系和篇幅，使其更符合目标期刊和医学论文表达。润色前后自动比较数字、引文和表图引用；冻结母稿保持不变，任何科学事实变化都必须撤销或回到来源修正并重新经过 S19。

输出：润色后的全文和变更检查记录。

#### S23｜生成并检查投稿包

仅根据目标期刊明确要求生成需要上传的文件。正文、title page、cover letter、补充方法和其他叙述性材料均生成 Word 文件，不会只把正文转成 DOCX 而把其余内容留成 Markdown。

Word 样式优先采用官方投稿指南；若指南没有规定，默认使用 Times New Roman、12 pt、双倍行距、黑色文字。净化器会从所有 WordprocessingML 部件移除 `keepNext`、`keepLines`、`pageBreakBefore`、`outlineLvl` 和段落边框，标题统一映射为基于正文样式的 `SectionHeading`，因而没有标题前小黑点、折叠三角形或可折叠大纲。文件同时移除超链接，统一同级标题字号，并拒绝字符 `↓` 和 Word 手动换行符。

正文必须有 References 标题，并且只能有一个 Figure legends 区标题；每幅图也只能出现一个对应图注标题，图注正文不得再次以 `Figure N` 开头。补充方法 DOCX 不允许包含表格或 Markdown 长横线残留，补充表只存在于单独的三线表工作簿中。如期刊要求，也可另交单独图注文件，但同一文件内仍不得重复标题。

所有 Word 文件都要经过结构检查和渲染后的视觉检查。若 title page 包含参考文献数量，Markdown 源文件和生成后的 DOCX 都必须与正文实际引用数量一致。图片、表格、补充材料、清单和 manifest 按目标期刊要求加入投稿包。

输出：完整投稿目录、DOCX 文件、图表、清单、manifest 和质量检查记录。

#### S24｜用户最终修改并确认投稿包

用户检查并可直接修改投稿包中的内容和格式。流程不会把“文件已交付”或之前对论文的确认当作对最终投稿包的确认，也不会盲目重建并覆盖用户编辑过的 DOCX。

投稿包中的期刊特定内容修改必须同步回 `08_submission/integration/` 的 Markdown 来源并重新生成 Word；方法、分析、结果或科学解释的实质修改则回到 S19 之前的真实来源，重新审核和冻结。纯 Word 排版修改可以留在 S24，但系统会比较 S23 保存的可见文字哈希：只有文字完全不变时才视为纯排版；在 Word 中直接增删文字会阻止冻结和终审。

这里同样允许不限次数的反馈。涉及科学内容时在 S19 调用来源阶段的规则修正并重新确认；只涉及期刊格式时留在 S24。两者都不清空后续阶段历史。每轮修改都必须完成受影响文件重建、结构检查和视觉检查，再重新交给用户确认，不会因为前一轮已经确认过就跳过本轮验证。

修改完成后，重新检查改变的文件。流程会明确询问：

> 投稿包已按您的修改重新校验。是否确认 OK，并调用一个独立子代理，以普通读者和期刊编辑的视角终审当前冻结版本？

只有用户明确回答 OK、确认或可以，才冻结这一版投稿包。

输出：人工修改记录、明确确认和不可混淆的冻结版本。

#### S25｜独立子代理以读者、编辑和合规视角做最终审查

把用户确认并冻结的投稿包、目标期刊信息和官方投稿指南交给一个只读独立子代理。它先把自己当作没有后台信息的普通科学读者，找出看不懂的段落、术语、逻辑跳跃、图表或图注；再以期刊编辑视角检查错别字、语法、标点、残留模板、重复或遗漏文字、术语与格式不一致等低级错误；最后核对必需文件、文件名和格式、字数与参考文献限制、作者和声明、图表及补充材料编号、跨文件标题/数值/版本是否一致，以及仍需在投稿系统中人工完成的事项。

每条问题必须指出具体文件及页码、标题、段落、表格单元格或图版位置，并区分必须修改、轻微错误和纯偏好。独立子代理只报告，不直接编辑用户确认过的冻结文件。

只有审查得到 `PASS` 才完成流程；如为 `REVISE`，修改后回到 S24，让用户再次查看和确认新的冻结版本，避免在用户确认后暗中改变投稿包。

输出：独立投稿审查报告和最终 PASS/REVISE 结论。

## 在 Codex 中如何启动

### 已安装用户级入口时

在任意项目、任意 Codex 对话中输入：

```text
$medpaper
```

或：

```text
/medpaper pipeline
```

可以在同一条消息后直接写研究任务，例如：

```text
/medpaper pipeline 我有一份回顾性队列数据，希望分析某暴露与院内死亡的关系并形成可投稿论文。
```

`/medpaper pipeline` 在当前配置中是 `$medpaper` 的文字别名，并不是 Codex 自带的原生斜杠命令。用户级 `$medpaper` 会从任何项目定位到已安装的工作流发布包，再在当前工作区启动或恢复项目。

同一项目、同一对话中启动一次后，后续直接说“修改 Methods……”“这版 Word 的标题格式不对”等即可，不必在每条消息前重复 `$medpaper`。磁盘中的工作流阶段和活动修订轮次负责约束后续操作；只有换到另一个对话或需要明确启动/恢复该项目时，才再次输入 `$medpaper` 或 `/medpaper pipeline`。

### 直接使用本仓库时

克隆后在 PowerShell 中运行：

```powershell
Set-Location <medpaper-codex-workflow目录>
uv run --python 3.13 python bootstrap.py
.\.venv\Scripts\python.exe tools\wf.py status
```

然后把该目录作为 Codex 项目打开，输入：

```text
$medpaper-codex-pipeline
```

仓库内入口只作用于本项目；用户级 `$medpaper` 才能在任意项目和对话中调用。GitHub 仓库本身不会自动覆盖本机已安装版本，需要重新安装或同步发布包后才会更新全局入口。

## 新项目与已有项目如何处理

- 新研究：把研究想法和用户提供的材料放到 `project/00_input/`，由 S01 开始。
- 已有数据：先登记数据来源、变量说明和已有分析，再从仍未满足的最早阶段开始。
- 已有论文：工作流会识别哪些证据链和检查缺失，不会仅因已有 Word 文件就跳过数字、文献和图表校验。
- 中断后恢复：状态保存在项目磁盘中，重新运行 `wf.py status` 即可看到当前阶段、缺失文件和下一步。

常用命令：

```powershell
.\.venv\Scripts\python.exe tools\wf.py status
.\.venv\Scripts\python.exe tools\wf.py check
.\.venv\Scripts\python.exe tools\wf.py advance --note "本阶段完成了什么、做了什么决定、还有什么问题"
.\.venv\Scripts\python.exe tools\wf.py doctor
.\.venv\Scripts\python.exe tools\wf.py tree -v
.\.venv\Scripts\python.exe tools\selftest.py
```

日常使用时，研究者通常只需要在 Codex 对话中描述任务和回答关键问题；这些命令主要用于安装、排错或人工检查流程状态。

```text

## 文献、隐私与合规边界

- 学术全文只通过开放获取或用户明确授权的机构访问路径获取；不使用非法下载源。
- 文献发现插件只能提供候选项，不能直接成为正式参考文献的唯一依据。
- 正式引用必须通过新鲜 PubMed EFetch 原始 XML、内容哈希、当前文献库哈希，以及 S13/S25 必做的独立实时复核和中间关口的短期、绑定哈希证据验证；不能把 `verified` 布尔值、编译成功或门禁变绿当作文献真实的证据。
- 未经用户明确授权，不把患者级数据、私密文件、浏览器 cookie、API 密钥或个人联系信息发送到外部插件或服务。
- 作者身份、基金、伦理审批、利益冲突和数据可用性均由用户提供，工作流不自行推断。
- 本工具辅助研究组织、分析、写作和质量检查，不代替研究者、统计师、伦理机构、期刊编辑或法律/临床专业意见。

$env:NCBI_API_KEY = "<你的 NCBI API key>"

```

不要把真实密钥或私人联系信息写入仓库。未配置 API key 时仍可使用公开访问速率。
